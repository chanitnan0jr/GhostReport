The report keeps self-report and event observations separate. Percent-based
status wording is presented without a bare percentage, using the exact
respondent count text alongside it. Low n is neutral/Unresolved. Conflict
badges use the actual report flag only when the evidence map's DP, hypothesis,
cohort, counts, text and labels match that report finding. Unknown conflict
status is not inferred from strings. H_other and generic labels remain visible.

Graph nodes support keyboard selection; controls preserve pan/zoom, while
node dragging, connections and deletion are disabled. Both graph libraries
are lazy-loaded after the report summary. CSS additions target laptop layout;
no new mobile implementation or mobile verification was performed.

## API contracts and limits

- /api/report: narrative.text/source/facts; current.population/sources,
  findings/by_source, sessions/session_sources and existing report panels.
- /api/journeys: unchanged columns/nodes/edges/segments/highlight behavior.
- /api/workflow?target=app|ens: nodes, legend, scope, source refs and review.
- /api/evidence: columns/nodes/edges/highlight/notes, used as provided.

No additional API fields were required. The evidence endpoint has no snapshot
version/cutoff or conflict flag. Its map refreshes after successful report
updates and shows its own receive time. Matching conflict flags come from the
main report, as described above; no atomic cross-endpoint snapshot is claimed.

Workflow edges are code associations, generated from state order and common
files; they are not collected event transitions. Facts with no state in their
file stay unattached. No missing permalink is synthesized.

Mock API adapters extend the shared report in memory, explicitly labeling its
sessions as seed. Journey paths are described as reconstructed UI previews.
The mock evidence map includes only known report links and explicitly omits
approved option/rule links absent from the fixture. Real API data supplies
the full map. No fixture files were edited.
